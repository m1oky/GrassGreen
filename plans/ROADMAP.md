# GrassGreen v4.0 — The Evolution (Архитектурный роадмап)

> **Статус:** Проектирование / Активная разработка  
> **Официальный домен:** `grassgreen.info`  
> **Репозиторий:** `github.com/m1oky/GrassGreen`  
> **Цель обновления 4.0:** Переход от экспериментальной Stack VM к автономному (freestanding) низкоуровневому системному языку с прямой табличной диспетчеризацией, C-ABI структурами, фирменным синтаксисом потоков ввода-вывода и оптимизированным компилятором `grg` (`grassc.exe`).

---

## 1. Архитектура ядра и рантайм (VM / Execution Core)

- [x] **Перевод языка в режим Freestanding (п. 6)**
  - Полная независимость от стандартных библиотек C++ (работа без libc / libc++ / iostream через модуль аппаратной абстракции GrassHAL).
  - Готовность ядра и всех стандартных библиотек к выполнению в bare-metal окружении, загрузчиках ОС и микроконтроллерах с сохранением 100% синтаксиса и ключевых слов.
- [x] **Аллокатор памяти для Freestanding: Arena Allocator (п. 15)**
  - Выделение непрерывного пула памяти под AST и байт-код с последовательным сдвигом указателя (`bump-pointer`).
  - Мгновенное освобождение памяти целых модулей в O(1) без фрагментации, вызовов `malloc`/`free` и утечек.
- [x] **Табличная диспетчеризация / Dispatch Table (п. 7)**
  - Уход от медленного цикла `while(switch)`.
  - Массив прямых указателей на обработчики опкодов для мгновенного перехода между инструкциями.
- [x] **Диспетчеризация через Labels-as-Values (п. 16)**
  - Использование механизма `computed goto` (`goto *dispatch_table[op]`) для прямого прыжка из конца текущей инструкции в начало следующей без проверок.
- [x] **Представление значений через NaN-Boxing (п. 14)**
  - Упаковка всех базовых типов (числа, булевы флаги, указатели, дескрипторы структур) в плоский 64-битный формат IEEE 754 (ровно 8 байт на значение).
  - Снижение нагрузки на L1-кэш процессора в 2 раза и ускорение передачи аргументов.
- [x] **Минимальный JIT-компилятор (п. 1)**
  - Генерация нативных машинных инструкций x86_64 для критических горячих участков байт-кода (горячие циклы и вычисления).
  - Модуль GrassJIT (`src/GrassJIT.h`, `src/GrassJIT.cpp`), выделение исполняемых страниц `PAGE_EXECUTE_READWRITE` / `GrassHAL::alloc_executable_memory`.
  - Прямой вызов скомпилированного нативного блока по Microsoft x64 ABI (`RCX = JitRuntimeContext*`) с SSE2 векторными регистрами `xmm0`, `xmm1` и возвратом через `ret (C3)`.
  - Автоматическая компиляция горячих циклов с ускорением и CLI флаг `--jit` (а также авто-включение в `-O3`).
- [x] **Многопоточность: `thread` / `async` (п. 12)**
  - Встроенная поддержка создания потоков и асинхронных задач на уровне ядра и байт-кода.
  - Синтаксис: `take t = thread(fn, args...)`, `take t = async(fn, args...)`, а также оператор запуска в фоне `async fn(args...);`.
  - Встроенные функции синхронизации: `thread_join(t)`, `thread_detach(t)`, `thread_id()`, `thread_sleep(ms)`.
  - Полноценные мьютексы: `mutex_create()`, `mutex_lock(m)`, `mutex_unlock(m)`, `mutex_destroy(m)`.
  - Модель разделяемой памяти: разделяемые глобальные переменные (`GrassSharedEnv`) с защитой от гонок данных и локальные контексты исполнения потоков.
  - Поддержка кооперативного выполнения в freestanding режиме (`GrassHAL::is_freestanding()`).

## 2. Фирменный синтаксис ввода-вывода (I/O Pipeline)

- [x] **Потоковый вывод: `gout` (Grass Output)**
  - Полная замена C++ команды `cout` на суверенный синтаксис GrassGreen:
    ```grass
    gout << "GrassGreen v4.0 loaded!" << endl;
    gout << "Score: " << score << " | Status: " << status << endl;
    ```
  - Сохранение удобного оператора сдвига/потока `<<` и манипулятора `endl` (вывод `\n` + сброс буфера).
  - Работа напрямую через системные вызовы OS (`WriteFile` в Win32 / `sys_write` в Linux) в обход `std::cout`.
- [x] **Потоковый ввод: `gin` (Grass Input)**
  - Фирменный поток чтения данных из терминала:
    ```grass
    gin >> user_input;
    ```

## 3. Данные, память и низкоуровневый доступ

- [x] **Пользовательские структуры: `struct` (п. 10)**
  - Синтаксис объявления составных типов данных:
    ```grass
    struct Player {
        hp: u32,
        x: u64
    }
    ```
  - Доступ к полям через точку с расчётом смещения в байтах на этапе компиляции.
- [x] **Оптимизация расположения структур: C-ABI Data Alignment (п. 17)**
  - Выравнивание полей структур по границам адресов (1, 4, 8 байт) в соответствии со стандартом C-ABI.
  - Совместимость структур памяти с нативными драйверами и кодом на C/C++.
- [x] **Динамические массивы: `array` (п. 2)**
  - Векторные структуры фиксированного и динамического размера с быстрой индексацией `arr[i]`.
- [x] **Аппаратный доступ к физической памяти: MMIO и `volatile` (п. 18)**
  - Прямое чтение и запись по фиксированным физическим и виртуальным адресам без кеширования компилятором (`mmio_read8/16/32/64`, `mmio_write8/16/32/64`).
  - Управление аппаратными портами ввода-вывода x86 (`inb/inw/inl`, `outb/outw/outl`, `io_in8/16/32`, `io_out8/16/32`).
  - Аппаратные барьеры памяти (`memory_barrier`, `read_barrier`, `write_barrier` на базе `mfence`, `lfence`, `sfence`).
  - Ключевое слово-квалификатор `volatile` для объявления переменных (`volatile take reg = ...`).
  - Двойной режим работы: прямое volatile обращение в bare-metal/freestanding режиме и эмуляция физической памяти (2 МБ low-memory с буфером VGA 0xB8000 + 64K I/O портов) на хосте.

## 4. Оптимизация байт-кода (Bytecode Optimizer)

- [x] **Bytecode Layout & Fusion Optimizer (п. 9)**
  - **Opcode Fusion:** объединение частых цепочек инструкций (`OP_CONST_NUM` + `OP_ADD/SUB/MUL/DIV` -> `OP_ADD_CONST`, `OP_SUB_CONST`, `OP_MUL_CONST`, `OP_DIV_CONST`; инкременты `OP_LOAD_VAR` + `+1` + `OP_STORE_VAR` -> `OP_INC_VAR`, `OP_DEC_VAR`) с мгновенным обновлением переменных без работы со стеком.
  - **Constant Folding:** свертка арифметических констант на этапе компиляции в одну плоскую константу.
  - **Dead Code Elimination & Jump Relocation:** устранение недостижимого байт-кода после безусловных `OP_RET`/`OP_JMP` с точным математическим пересчетом всех адресов переходов.
  - **Уровни оптимизации:** поддержка флагов `-O0` (отключено), `-O1` (Peephole + Constant Folding), `-O2` (Opcode Fusion + DCE), `-O3` (многопроходный Fixpoint). Ускорение циклов в 2.6 раза.

## 5. Модульность, библиотеки и импорт

- [x] **Склейка AST и разрешение зависимостей: Import Pass (п. 8)**
  - Разрешение зависимостей между файлами проекта на этапе формирования синтаксического дерева с рекурсивным обходом.
  - Каноническая нормализация путей и семантика `#pragma once` (защита от циклов и алмазных зависимостей Diamond Problem).
  - Поддержка автономной виртуальной файловой системы RamFS в режиме `--freestanding`.
- [x] **Настоящий импорт файлов: `import` / `include` (п. 11)**
  - Возможность писать полноценные модули, структуры и вспомогательные функции на самом языке `.grass`.
  - Поддержка синтаксисов: `import "module.grass";`, `import "module";`, `import module;`, `include "module";`, `#include <module.grass>`.
  - Встраивание структур (`struct`), пользовательских функций (`take fn()`, `int fn()`, `void fn()`) и директив библиотек из импортированных модулей с прямым вызовом из `main()`.

## 6. Компилятор, CLI и экосистема инструментария

- [x] **Ребрендинг экосистемы: `G&G` (п. 19)**
  - Официальное сокращённое наименование проекта: **G&G** (*Grass & Green*).
  - Бинарник компилятора в терминале: **`grg`** (в среде Windows — `grassc.exe` / `grg.exe`).
- [x] **Флаги командной строки компилятора (п. 20)**
  - `-o <filename>` — имя выходного файла.
  - `-c` — собрать только чистый бинарный байт-код (`.grassc`), не упаковывая его в `.exe`.
  - `-emit-exe` — упаковать байт-код вместе с нативным загрузчиком Win32 PE в один автономный `.exe`.
  - `-O0` (Debug) — мгновенная сборка без оптимизаций для быстрой проверки логики.
  - `-O2` / `-O3` — включить полный оптимизатор байт-кода (Opcode Fusion, Hot/Cold Splitting, выравнивание кэша).
  - `--dump-ast` — распечатать в терминал наглядное дерево AST.
  - `-S` — распечатать читаемый сырой дизассемблер байт-кода.
  - `--time` — замерить и вывести в консоль время каждого этапа компиляции с точностью до миллисекунд.
  - `--freestanding` — собрать ядро в автономном режиме без вызовов стандартной библиотеки для работы на голом железе.
  - `-V` / `--version` — вывести версию: `GrassGreen (G&G) v4.0.0 (x86_64-win32)`.
  - `-h` / `--help` — напечатать структурированную справку по всем командам и флагам.
  - `--ru` / `--en` — выбор языка вывода компилятора (**основной по умолчанию: английский**, с возможностью переключения на русский по флагу `--ru`).
- [x] **Интеграция в системный PATH и графический установщик (п. 5)**
  - Полноценный автономный графический инсталлятор `setup.exe` (Win32 GUI в фирменной темной теме GrassGreen).
  - Упаковка компилятора `grg.exe`, `grassc.exe`, командных лаунчеров `grg.cmd`, `grass.cmd`, `gg.cmd` и демо-скриптов прямо в тело установщика (`payload_data.h`).
  - Автоматическая запись пути установки в пользовательский (`HKCU\Environment\Path`) и системный (`HKLM`) PATH.
  - Мгновенное оповещение Windows через `WM_SETTINGCHANGE` без необходимости перезагрузки системы.
  - Регистрация файловых ассоциаций для скриптов `.grass` и создание ярлыка консоли на Рабочем столе.
  - Поддержка тихого автоматического режима установки (`setup.exe /silent` / `-s`).
  - Полная доступность утилиты `grg` из любой папки операционной системы.
