# 🚀 GrassGreen v4.0 — The Evolution (Архитектурный роадмап)

> **Статус:** Проектирование / Активная разработка  
> **Официальный домен:** `grassgreen.info`  
> **Репозиторий:** `github.com/m1oky/GrassGreen`  
> **Цель обновления 4.0:** Переход от экспериментальной Stack VM к автономному (freestanding) низкоуровневому системному языку с прямой табличной диспетчеризацией, C-ABI структурами, фирменным синтаксисом потоков ввода-вывода и оптимизированным компилятором `grg` (`grassc.exe`).

---

## 1. Архитектура ядра и рантайм (VM / Execution Core)

- [ ] **Перевод языка в режим Freestanding (п. 6)**
  - Полная независимость от стандартных библиотек C++ (работа без libc / libc++ / iostream).
  - Готовность ядра к выполнению в bare-metal окружении, загрузчиках ОС и микроконтроллерах.
- [ ] **Аллокатор памяти для Freestanding: Arena Allocator (п. 15)**
  - Выделение непрерывного пула памяти под AST и байт-код с последовательным сдвигом указателя (`bump-pointer`).
  - Мгновенное освобождение памяти целых модулей в O(1) без фрагментации, вызовов `malloc`/`free` и утечек.
- [ ] **Табличная диспетчеризация / Dispatch Table (п. 7)**
  - Уход от медленного цикла `while(switch)`.
  - Массив прямых указателей на обработчики опкодов для мгновенного перехода между инструкциями.
- [ ] **Диспетчеризация через Labels-as-Values (п. 16)**
  - Использование механизма `computed goto` (`goto *dispatch_table[op]`) для прямого прыжка из конца текущей инструкции в начало следующей без проверок.
- [ ] **Представление значений через NaN-Boxing (п. 14)**
  - Упаковка всех базовых типов (числа, булевы флаги, указатели, дескрипторы структур) в плоский 64-битный формат IEEE 754 (ровно 8 байт на значение).
  - Снижение нагрузки на L1-кэш процессора в 2 раза и ускорение передачи аргументов.
- [ ] **Минимальный JIT-компилятор (п. 1)**
  - Генерация нативных машинных инструкций x86_64 для критических горячих участков байт-кода (горячие циклы и вычисления).
- [ ] **Многопоточность: `thread` / `async` (п. 12)**
  - Встроенная поддержка создания потоков и асинхронных задач на уровне ядра.

## 2. Фирменный синтаксис ввода-вывода (I/O Pipeline)

- [ ] **Потоковый вывод: `gout` (Grass Output)**
  - Полная замена C++ команды `cout` на суверенный синтаксис GrassGreen:
    ```grass
    gout << "GrassGreen v4.0 loaded!" << endl;
    gout << "Score: " << score << " | Status: " << status << endl;
    ```
  - Сохранение удобного оператора сдвига/потока `<<` и манипулятора `endl` (вывод `\n` + сброс буфера).
  - Работа напрямую через системные вызовы OS (`WriteFile` в Win32 / `sys_write` в Linux) в обход `std::cout`.
- [ ] **Потоковый ввод: `gin` (Grass Input)**
  - Фирменный поток чтения данных из терминала:
    ```grass
    gin >> user_input;
    ```

## 3. Данные, память и низкоуровневый доступ

- [ ] **Пользовательские структуры: `struct` (п. 10)**
  - Синтаксис объявления составных типов данных:
    ```grass
    struct Player {
        hp: u32,
        x: u64
    }
    ```
  - Доступ к полям через точку с расчётом смещения в байтах на этапе компиляции.
- [ ] **Оптимизация расположения структур: C-ABI Data Alignment (п. 17)**
  - Выравнивание полей структур по границам адресов (1, 4, 8 байт) в соответствии со стандартом C-ABI.
  - Совместимость структур памяти с нативными драйверами и кодом на C/C++.
- [ ] **Динамические массивы: `array` (п. 2)**
  - Векторные структуры фиксированного и динамического размера с быстрой индексацией `arr[i]`.
- [ ] **Аппаратный доступ к физической памяти: MMIO и `volatile` (п. 18)**
  - Прямое чтение и запись по фиксированным физическим адресам без кеширования компилятором.
  - Необходимо для управления портами ввода-вывода и написания низкоуровневых драйверов.

## 4. Оптимизация байт-кода (Bytecode Optimizer)

- [ ] **Bytecode Layout & Fusion Optimizer (п. 9)**
  - **Opcode Fusion:** объединение частых цепочек инструкций (например, `LOAD` + `ADD` -> `FUSED_ADD`) в один быстрый опкод.
  - **Hot/Cold Splitting:** разделение горячих путей выполнения и редких веток (обработка ошибок) для идеального кэширования L1I.
  - **Cache Alignment:** выравнивание адресных переходов под 64-байтные строки кэша процессора.

## 6. Компилятор, CLI и экосистема инструментария

- [ ] **Ребрендинг экосистемы: `G&G` (п. 19)**
  - Официальное сокращённое наименование проекта: **G&G** (*Grass & Green*).
  - Бинарник компилятора в терминале: **`grg`** (в среде Windows — `grassc.exe` / `grg.exe`).
- [ ] **Флаги командной строки компилятора (п. 20)**
  - `-o <filename>` — имя выходного файла.
  - `-c` — собрать только чистый бинарный байт-код (`.grassc`), не упаковывая его в `.exe`.
  - `-emit-exe` — упаковать байт-код вместе с нативным загрузчиком Win32 PE в один автономный `.exe`.
  - `-O0` (Debug) — мгновенная сборка без оптимизаций для быстрой проверки логики.
  - `-O2` / `-O3` — включить полный оптимизатор байт-кода (Opcode Fusion, Hot/Cold Splitting, выравнивание кэша).
  - `--dump-ast` — распечатать в терминал наглядное дерево AST.
  - `-S` — распечатать читаемый сырой дизассемблер байт-кода.
  - `--time` — замерить и вывести в консоль время каждого этапа компиляции с точностью до миллисекунд.
  - `--freestanding` — собрать ядро в автономном режиме без вызовов стандартной библиотеки для работы на голом железе.
  - `-V` / `--version` — вывести версию: `GrassGreen (G&G) v4.0.0 (x86_64-win32)`.
  - `-h` / `--help` — напечатать структурированную справку по всем командам и флагам.
  - `--ru` / `--en` — выбор языка вывода компилятора (**основной по умолчанию: английский**, с возможностью переключения на русский по флагу `--ru`).
- [ ] **Интеграция в системный PATH (п. 5)**
  - Доступность утилиты `grg` из любой папки операционной системы.
