# 🚀 GrassGreen v4.0 — The Evolution (Архитектурный роадмап)

> **Статус:** Проектирование / Активная разработка  
> **Цель:** Переход от экспериментальной Stack VM к автономному (freestanding) низкоуровневому системному языку с прямой табличной диспетчеризацией, C-ABI структурами и оптимизированным компилятором.

---

## 1. Архитектура ядра и рантайм (VM / Execution)
- [ ] **Перевод языка в режим Freestanding (п. 6)**
  - Полная независимость от стандартной библиотеки C++ (работа без libc / libc++).
  - Готовность ядра к работе в bare-metal окружении и загрузчиках ОС.
- [ ] **Аллокатор памяти для Freestanding: Arena Allocator (п. 15)**
  - Выделение непрерывного пула памяти под AST и байт-код с последовательным сдвигом указателя (`bump-pointer`).
  - Мгновенное освобождение памяти модулей без рекурсивных обходов и утечек.
- [ ] **Табличная диспетчеризация / Dispatch Table (п. 7)**
  - Уход от медленного цикла `while(switch)`.
  - Массив прямых указателей на обработчики опкодов для мгновенного перехода.
- [ ] **Диспетчеризация через Labels-as-Values (п. 16)**
  - Использование computed goto (`goto *dispatch_table[op]`) для прямого прыжка из конца одной инструкции в начало следующей.
- [ ] **Представление значений через NaN-Boxing (п. 14)**
  - Упаковка всех базовых типов, указателей и дескрипторов в плоский 64-битный формат IEEE 754 (8 байт на значение).
  - Снижение нагрузки на L1-кэш процессора в 2 раза.
- [ ] **Минимальный JIT (п. 1)**
  - Компиляция критических горячих участков байт-кода напрямую в машинные инструкции.

---

## 2. Данные, память и низкоуровневый доступ
- [ ] **Пользовательские структуры: `struct` (п. 10)**
  - Синтаксис объявления составных типов: `struct Player { hp: u32, x: u64 }`.
  - Доступ к полям через точку с расчётом смещения в байтах.
- [ ] **Оптимизация расположения структур: C-ABI Data Alignment (п. 17)**
  - Выравнивание полей структур по границам адресов (1, 4, 8 байт).
  - Совместимость с бинарными форматами железа и нативным C.
- [ ] **Динамические массивы: `array` (п. 2)**
  - Векторные структуры фиксированного и динамического размера с индексацией `arr[i]`.
- [ ] **Аппаратный доступ к памяти: MMIO и volatile-операции (п. 18)**
  - Встроенные функции прямого чтения/записи физической памяти: `raw_read32(addr)` и `raw_write32(addr, val)`.
  - Флаг `volatile` для запрета компилятору оптимизировать или удалять обращения к регистрам устройств и видеопамяти.

---

## 3. Компилятор, AST и модульность
- [ ] **Склейка AST и разрешение зависимостей: Import Pass (п. 8, 11)**
  - Настоящий модульный импорт файлов: `import "lib.grass";`.
  - Защита от циклических зависимостей через локальный реестр модулей (`Module Registry`).
  - Объединение синтаксических деревьев на этапе лексера / AST без загрязнения пространств имён.
- [ ] **Оптимизатор структуры байт-кода: Bytecode Layout & Fusion Optimizer (п. 9)**
  - **1. Fusion pass:** объединение частых связок соседних опкодов в одиночные супер-инструкции.
  - **2. Hot/Cold splitting:** разделение горячих циклов и редких веток аварийных остановок/паник для экономии инструкционного кэша.
  - **3. Cache alignment:** выравнивание адресов функций и меток переходов по 16/32 байта для конвейера процессора.
- [ ] **Многопоточность: `thread` / `async` (п. 12)**
  - Базовые примитивы запуска асинхронных потоков для сетевых и фоновых задач.

## 4. Тулчейн, экосистема и IDE
- [ ] **Добавление языка в системный PATH (п. 5)**
  - Автоматическая регистрация исполняемого пути тулчейна для вызова `grass` из любого терминала.
- [ ] **Официальное расширение для VS Code (п. 13)**
  - **Нормальная подсветка кода по всем библиотекам (п. 4):** грамматика TextMate для подсветки ключевых слов, типов и структур.
  - **Автодополнение по встроенным библиотекам (п. 3):** сниппеты и подсказки сигнатур встроенных функций и модулей.
