# Библиотека !baremetal! — Окружение голого железа, терминала и операционной системы

Библиотека **`!baremetal!`** (псевдонимы: `!bm!`, `!kernel!`, `!BareMetal!`, а также автоматически подключается при директивах `!vd+!`, `!VD+!`, `!vd!`, `!VD!`) предоставляет специализированный инструментарий для прямого взаимодействия с терминалом, аппаратными компонентами машины и автономной средой операционной системы (RQWos / Bare-Metal ядро GrassGreen).

Библиотека исключает зависимость от внешних платформ при создании автономных программ, терминальных оболочек, интерфейсов TUI и загрузочных образов операционных систем. Поддерживается выполнение как в виртуальной машине GrassVM, так и на аппаратном уровне компьютера без ОС (`--kernel`, `--multiboot`, `--iso`, `--freestanding`).

*Примечание:* Директива `!gui!` относится к библиотеке оконного интерфейса `!interface!` и не активирует `!baremetal!`. Для активации bare-metal окружения используйте `!baremetal!` или `!vd+!`.

---

## Подключение библиотеки

```grass
!GrassGreen!
!baremetal!

int main() {
    // Код для работы с терминалом и bare-metal ядром
    return 0;
}
```

| `color(fg, bg)` | `int` | Устанавливает цвет текста `fg` и цвет фона `bg`. Поддерживает строковые имена, числа и HEX. |

## 2. Очистка экрана и защита строк от стирания

В интерактивных терминалах и системных консолях требуется очищать экран для обновления вывода, сохраняя постоянную шапку, статус-бар или логотип операционной системы. Для этого библиотека предоставляет механизм защищенных строк `not_clear`.

| Инструкция / Функция | Описание |
| :--- | :--- |
| `clear;` / `clear()` / `cls;` / `cls()` | Аппаратная очистка экрана. Все строки, выведенные под защитой режима `not_clear`, автоматически перерисовываются на экране сразу после очистки. |
| `clear_all()` / `cls_all()` | Полная очистка экрана со сбросом внутреннего буфера защищенных строк. |
| `not_clear { ... }` | Блочная инструкция. Весь консольный вывод внутри фигурных скобок автоматически фиксируется в буфере защищенных строк. |
| `not_clear;` / `not_clear_on()` / `not_clear(1)` | Включает режим постоянной фиксации выводимых строк. Последующий вывод `gout` запоминается и восстанавливается при `clear`. |
| `clearable;` / `not_clear_off()` / `not_clear(0)` | Отключает режим фиксации строк. Последующий вывод будет стираться стандартно. |

## 3. Посимвольный опрос клавиатуры

Для создания интерактивных интерфейсов, игр и системных оболочек функция `read_key()` считывает нажатие клавиши в сыром режиме без ожидания подтверждения клавишей Enter.

| Функция | Возвращает | Описание |
| :--- | :--- | :--- |
| `read_key()` | `string` | Блокирующее чтение одной клавиши. Возвращает печатный символ или строковое имя служебной клавиши. |

### Возвращаемые строковые коды клавиш
- **Печатные символы:** `"a"`, `"B"`, `"1"`, `";"`, `"/"` и другие.
- **Управляющие клавиши:** `"ENTER"`, `"ESC"`, `"SPACE"`, `"BACKSPACE"`, `"TAB"`.
- **Стрелки навигации:** `"UP"`, `"DOWN"`, `"LEFT"`, `"RIGHT"`.
- **Навигация по документу:** `"HOME"`, `"END"`, `"DELETE"`, `"PAGE_UP"`, `"PAGE_DOWN"`.
- **Расширенные коды:** `"EXT_<код>"` для специальных клавиатурных последовательностей.

## 4. Виджеты текстового интерфейса (TUI)

Библиотека содержит готовые процедуры отрисовки консольных графических элементов:

| Функция | Возвращает | Описание |
| :--- | :--- | :--- |
| `draw_box(x, y, w, h, [title], [fg], [bg])` | `int` | Отрисовывает прямоугольную рамку шириной `w` и высотой `h` с левым верхним углом в координатах `(x, y)`. Опционально принимает заголовок `title`, цвет границы `fg` (по умолчанию `light_green`) и цвет фона `bg` (по умолчанию `black`). |
| `menu(title, options)` | `int` | Запускает интерактивное меню с заголовком `title` и списком пунктов `options` (массив строк). Пользователь выбирает пункт стрелками `UP`/`DOWN` и подтверждает выбор клавишами `ENTER` или `SPACE`. Возвращает нулевой индекс выбранного элемента или `-1` при отмене клавишей `ESC`. |
| `progress_bar(x, y, width, percent, [fg], [bg])` | `int` | Отрисовывает индикатор выполнения в координатах `(x, y)` общей длиной `width` символов со степенью заполнения `percent` (от `0` до `100`). Формат вывода: `[=====.....] 50%`. |

## 5. Управление питанием ПК

Низкоуровневые вызовы для перезагрузки и выключения оборудования:

| Инструкция / Функция | Описание |
| :--- | :--- |
| `reboot;` / `reboot()` | Выполняет аппаратную перезагрузку системы. В среде автономного ядра задействует порт PCI 0xCF9, сброс через контроллер клавиатуры 8042 (порт 0x64) и тройное прерывание процессора (Triple Fault). |
| `poweroff;` / `poweroff()` | Выполняет отключение питания компьютера. В автономном ядре задействует порты ACPI/QEMU (0x604), Bochs (0xB004), VirtualBox (0x4004) и APM, либо завершает работу виртуальной машины. |

## 6. Виртуальная и физическая файловая система (RamFS / VFS)

Библиотека содержит встроенную файловую систему в оперативной памяти (RamFS / VFS). Она позволяет развернуть структуру файлов и папок без наличия физического накопителя, либо импортировать каталоги с хост-системы.

### Декларативная структура `virtual_struct`

Синтаксис `virtual_struct { ... }` позволяет прямо в коде программы описать иерархию папок и файлов. Поддерживаются ключевые слова `folder` и `dir` для создания каталогов, а также `file` для создания файлов с начальным содержимым:

```grass
virtual_struct {
    folder system {
        file "kernel.sys", "GrassGreen Kernel v4.3.0";
        file "config.sys", "DISPLAY=VGA;MODE=TEXT_80X25;GUI=VD+";
    };
    dir users {
        file "readme.txt", "Welcome to RQWos Bare-Metal!";
    };
    folder apps {};
    file "autorun.bat", "gui";
    file "notes.txt";
};
```

Внутри блока `virtual_struct` имена папок и файлов могут задаваться как строковыми литералами (`"readme.txt"`), так и прямыми идентификаторами (`system`). Допускается также размещение любых исполняемых выражений языка.

### Команды и функции управления VFS

Команды навигации по VFS поддерживают как вызов в форме функций с круглыми скобками, так и лаконичный терминальный синтаксис команд без скобок:

| Инструкция / Функция | Возвращает | Описание |
| :--- | :--- | :--- |
| `physical_struct("host_path")` | `int` | Рекурсивно сканирует и импортирует физическую директорию хост-системы `host_path` в корень виртуальной RamFS. |
| `pwd;` / `pwd()` | `string` | Отображает и возвращает текущий рабочий путь в VFS (например, `"/"` или `"/system"`). При вызове выводит путь в консоль. |
| `cd <path>;` / `cd("<path>")` | `int` | Переходит в указанный каталог VFS (`cd system;`, `cd ..;`, `cd /;`). Инструкция `cd;` без аргументов переходит в корневой каталог `"/"`. Возвращает `1` при успехе, `0` при ошибке. |
| `ls;` / `ls([flags])` | `string` | Отображает и возвращает содержимое текущей директории. Папки выводятся в квадратных скобках (например, `[system]`). Флаг `"-a"` включает показ скрытых файлов. *(Требует предварительной инициализации через `virtual_struct` или `physical_struct`)*. |
| `cr_folder("name")` | `int` | Создает новую папку с указанным именем в текущей директории VFS. |
| `cr_file("name", ["content"])` | `int` | Создает новый файл с опциональным содержимым в текущей директории VFS. |
| `copy("src", "dst")` | `int` | Копирует файл `src` в файл `dst` в пределах текущей директории. |
| `move("src", "dst")` | `int` | Перемещает или переименовывает файл `src` в `dst`. |
| `delete("path")` | `int` | Удаляет файл или каталог с указанным именем. |
| `cat <file>;` / `cat("<path>")` / `read_file("<path>")` | `string` | Читает и выводит в консоль текстовое содержимое файла из VFS, возвращая его строкой. |
| `not_show("name")` | `int` | Устанавливает файлу или каталогу признак скрытого (исключает из стандартного вывода `ls`). |
| `specSign_show(flag)` | `int` | Управляет глобальным отображением скрытых элементов (`"-a"` — показывать скрытые, `"-h"` или `"hide"` — скрывать). |

*Особенность вывода:* Команды `ls`, `pwd` и `cat` автоматически печатают результат в терминал. Поэтому при их вызове отдельный вывод через `gout << pwd() << endl;` не требуется — достаточно вызвать `pwd;` или `cat("file.txt");`.

## 7. Командный интерпретатор и графическая среда VD+

| Функция | Возвращает | Описание |
| :--- | :--- | :--- |
| `bm_exec("cmd")` | `int` | Передает строку команды во встроенный интерпретатор командной строки RQWos Baremetal. |
| `gui;` / `gui()` / `vd;` / `vd()` / `vd_desktop;` / `vd_desktop()` | `int` | Запускает псевдографическую консольную среду VD+ Desktop со сводкой состояния ядра, файловой системы и системных компонентов. |

### Команды интерпретатора `bm_exec`:
- `help` — вывод списка встроенных команд.
- `ls [-a]` — список файлов и папок текущего каталога.
- `cd <папка>` — переход в директорию.
- `pwd` — печать текущего рабочего пути.
- `cat <файл>` / `read <файл>` — просмотр содержимого файла.
- `disp` — опрос диспетчера памяти и аппаратных ресурсов.
- `gui` / `vd` / `desktop` — открытие среды VD+ Desktop.
- `clear` / `cls` — очистка терминала с сохранением шапки `not_clear`.
- `reboot` — аппаратная перезагрузка.
- `poweroff` — выключение питания машины.

## 8. Компиляция автономных ядер и загрузочных образов (GrassBoot)

Компилятор GrassGreen (`grassc` / `grg`) предоставляет выделенный пайплайн для сборки автономных bare-metal программ, ядер операционных систем и загрузочных образов без сторонних утилит:

| Флаг компилятора | Выходной формат | Описание |
| :--- | :--- | :--- |
| `--kernel` | `.bin` | Компиляция в чистый бинарный образ ядра с точкой входа `0x00100040` и заголовком спецификации Multiboot 1/2. |
| `--multiboot` | `.bin` | Генерация бинарного ядра, совместимого со спецификацией загрузчиков GRUB и QEMU. |
| `--iso` | `.iso` | Создание автономного загрузочного ISO-образа компакт-диска (стандарт El Torito No-Emulation, 38 секторов). Готов для записи на USB-флешку или запуска в QEMU/VirtualBox. |
| `--sys` | `.sys` | Компиляция системного драйвера / модуля ядра в формате GSYS. |
| `--freestanding` | Любой | Режим компиляции без привязки к стандартным рантайм-библиотекам хост-ОС. |

### Примеры команд сборки и запуска в эмуляторе:

```bash
# Сборка сырого бинарного ядра операционной системы
grassc --kernel -o kernel.bin main.grass

# Сборка загрузочного ISO-образа
grassc --iso -o myos.iso main.grass

# Запуск скомпилированного ядра напрямую через QEMU
qemu-system-x86_64 -kernel kernel.bin

# Запуск загрузочного ISO-диска в QEMU
qemu-system-x86_64 -cdrom myos.iso
```

## 9. Практические примеры

### Пример 1. Фиксация шапки консоли и динамический терминал

```grass
!GrassGreen!
!baremetal!

int main() {
    color("light_green", "black");

    // Фиксированный заголовок, который не стирается последующими clear
    not_clear {
        gout << "========================================" << endl;
        gout << "  RQWos KERNEL v4.3.0 | BAREMETAL CONSOLE" << endl;
        gout << "========================================" << endl;
    }

    gout << "Загрузка системных модулей..." << endl;
    gout << "Инициализация контроллеров прерываний..." << endl;

    // Очистка экрана: промежуточные строки сотрутся, а заголовок сохранится
    clear;

    gout << "Терминал готов к приему команд." << endl;
    return 0;
}
```

### Пример 2. Интерактивное TUI-меню и индикатор выполнения

```grass
!GrassGreen!
!baremetal!

int main() {
    clear;
    draw_box(2, 2, 45, 12, "СИСТЕМНОЕ МЕНЮ", "light_cyan", "black");

    take options = [
        "1. Запуск графической среды VD+",
        "2. Проверить целостность RamFS",
        "3. Перезагрузить систему",
        "4. Выключить питание"
    ];

    take choice = menu("Выберите действие:", options);

    if (choice == 0) {
        gui;
    } else if (choice == 1) {
        draw_box(5, 15, 40, 5, "Проверка RamFS", "yellow", "black");
        for (take p = 0; p <= 100; p = p + 25) {
            progress_bar(7, 17, 34, p, "light_green", "black");
        }
    } else if (choice == 2) {
        reboot;
    } else if (choice == 3) {
        poweroff;
    }

    return 0;
}
```

### Пример 3. Виртуальная файловая структура и навигация

```grass
!GrassGreen!
!baremetal!

int main() {
    // Декларативное создание иерархии RamFS
    virtual_struct {
        folder system {
            file "kernel.sys", "GrassGreen Kernel v4.3.0";
            file "boot.cfg", "TIMEOUT=5;DEFAULT=0";
        };
        dir docs {
            file "manual.txt", "RQWos Baremetal Reference Guide";
        };
        file "autorun.bat", "gui";
    };

    // Навигация и вывод содержимого
    cd system;
    pwd;

    gout << "Список файлов в каталоге:" << endl;
    ls;

    gout << "Содержимое kernel.sys:" << endl;
    cat("kernel.sys");

    // Выполнение команды через встроенный интерпретатор
    bm_exec("pwd");
    return 0;
}
```

### Пример 4. Автономное bare-metal ядро для сборки в ISO

```grass
!GrassGreen!
!baremetal!

int main() {
    color("light_cyan", "black");
    clear;

    not_clear {
        gout << "=================================================" << endl;
        gout << "     GRASSGREEN STANDALONE BARE-METAL KERNEL     " << endl;
        gout << "=================================================" << endl;
    }

    color("light_green", "black");
    gout << "Multiboot Handshake: OK" << endl;
    gout << "Hardware Initialization Complete." << endl;

    virtual_struct {
        folder init {
            file "startup.log", "System initialized successfully.";
        };
    };

    cd init;
    ls;

    return 0;
}
```
