## 1. Что полностью сделано и протестировано (DoD)

### 1.1. Полный де-хардкодинг ядра (устранение RQWos)
- Полностью удалена 726-строчная захардкоженная процедура `addr_vd_desktop` из `src/GrassBoot.cpp`.
- Удалены фиксированные 6 вкладок («1. СИСТЕМА», «2. ФАЙЛЫ» и др.), тестовые карточки мониторинга и нижний док.
- Во всех файлах репозитория устранено 100% упоминаний RQWos (0 вхождений).
- Удалены устаревшие файлы `notes.app` и `readme.txt` из RamFS.

### 1.2. Оживление опкодов OP_UI_CMD (0x73) и OP_UI_SHOW (0x72)
- Парсер `src/GrassSyntax.cpp` компилирует декларативные блоки GrassGreen (`window`, `tab`, `button`, `label`, `enter`, `header`, `click-switch`, `color`, `theme` и т.д.) в опкоды `OP_UI_CMD` и `OP_UI_SHOW`.
- Добавлена поддержка синтаксиса блока `header("dots") { title(...); color(...); text-color(...); }`.
- В `src/GrassBoot.cpp` реализован предварительный сканер байт-кода и заполнение структуры `KernelWindow g_kwin`.
- Процедура `addr_vd_desktop` генерируется **динамически** на основе высокоуровневого кода пользователя:
  - Инициализация видеорежима BGA с авто-чтением PCI BAR0 (`0x80001010` через порты `0x0CF8` / `0x0CFC`).
  - Отрисовка фона окна (`bg_color`).
  - Отрисовка заголовка с тремя точками macOS-стиля (`#ef4444`, `#f59e0b`, `#22c55e`) и строкой заголовка.
  - Динамическая отрисовка активной вкладки и ее виджетов.

### 1.3. Двусвязный аллокатор динамической памяти (kmalloc / kfree)
- Реализован в `src/GrassBoot.cpp` (процедуры `addr_kmalloc` и `addr_kfree`) в адресном пространстве `0x00200000 – 0x07FFFFFF` (126 МБ).
- Структура заголовка блока `KernelBlockHeader` (24 байта):
  - `magic` = `0x47474D4D` ("GGMM")
  - `size` = размер полезной нагрузки (выравнивание по 8 байт)
  - `is_free` = флаг свободы (1 = свободен, 0 = занят)
  - `next` = указатель на следующий заголовок
  - `prev` = указатель на предыдущий заголовок
- Алгоритм First-Fit с расщеплением блока при остатке $\ge 40$ байт.
- Двунаправленное слияние (coalescing) смежных свободных блоков при `kfree`.

### 1.4. Динамические массивы и структуры на Bare-Metal
- Заменены заглушки на реальный x86 машинный код с аллокацией через `kmalloc`:
  - `OP_NEW_ARRAY` (0x80): выделение буфера `count * 8 + 8` байт, запись размера и емкости.
  - `OP_GET_INDEX` (0x81): чтение элемента по индексу с проверкой границ.
  - `OP_SET_INDEX` (0x82): запись элемента по индексу.
  - `OP_ARRAY_PUSH` (0x83): добавление элемента с авто-реаллокацией (удвоение емкости через `kmalloc` + копирование `rep movsd`).
  - `OP_ARRAY_POP` (0x84): извлечение последнего элемента.
  - `OP_NEW_STRUCT` (0x85): создание структуры со словарём полей.
  - `OP_GET_FIELD` (0x86): чтение поля по 32-битному FNV1a-хешу имени поля.
  - `OP_SET_FIELD` (0x87): запись поля по хешу.

### 1.5. Интерактивное переключение вкладок
- Обнаружен и устранен баг переполнения 8-битного смещения условных переходов (`0x75 rel8` заменены на 32-битные `0x0F 0x85 rel32`), из-за которого длинный список виджетов переполнял `int8_t` и приводил к прыжкам назад.
- Проведено сквозное тестирование переключения между вкладками `desktop` и `terminal` в QEMU:
  - Сгенерированы битмапы `tab_desktop.bmp` и `tab_terminal.bmp`.
  - Попиксельный анализ подтвердил корректное переключение: 30 899 пикселей изменены, виджеты первой вкладки стёрты фоном, виджеты второй вкладки корректно отрисованы.

## 2. Что осталось / задачи на будущие релизы (Backlog)

Ниже перечислены задачи, которые не входили в текущее ТЗ на рефакторинг ядра v4.4.0, но могут быть реализованы следующими шагами:

1. **Полноценная файловая система FAT32/ext2 на диске:**
   - Сейчас в ядре работает RamFS с прямой синхронизацией секторов ATA PIO (LBA28).
   - *Задача:* добавить парсер структуры таблиц разделов MBR/GPT и файловой системы FAT32 для чтения и сохранения файлов на реальный жесткий диск/флешку.

2. **Сетевой стек TCP/IP поверх RTL8139:**
   - Сейчас сетевой драйвер RTL8139 инициализирован и принимает сырые фреймы (поддерживает базовые ARP и ICMP echo).
   - *Задача:* реализовать транспортный уровень TCP/UDP в bare-metal рантайме для полноценной работы встроенных веб-функций (`OP_START_WEB`, `serve()`) прямо на голом железе.

3. **Вытесняющая многозадачность (Preemptive Multitasking):**
   - Сейчас ядро работает в кооперативно-событийном цикле (Interactive Event Loop).
   - *Задача:* настроить прерывание системного таймера PIT (IRQ0, 100 Гц), стек TSS и планировщик задач (Round-Robin) для фонового выполнения потоков (`spawnThread`).

4. **Аппаратное 2D/3D ускорение (VMSVGA / VirtIO-GPU):**
   - Сейчас графика отрисовывается программно в линейный фреймбуфер Bochs BGA (быстрый `rep stosd`).
   - *Задача:* добавить поддержку команд 2D-акселерации VirtIO-GPU для виртуалок современного типа.

## 3. Как запустить и проверить результат

1. **Компиляция ОС из исходников GrassGreen:**
   ```powershell
   cd C:\Users\m1oky\Desktop\GrassGreen-v-4-1-0
   .\bin\grg.exe --iso examples/my_custom_os.grass -o custom_os.iso
   ```

2. **Запуск в QEMU:**
   ```powershell
   & "C:\Program Files\qemu\qemu-system-i386.exe" -cdrom custom_os.iso -m 256M -serial stdio
   ```
   В окне QEMU отобразится кастомная ОС пользователя с заголовком «My Sovereign OS — v1.0», кнопками и вкладками. Нажатие клавиш `1` и `2` (или клик мышью) переключает вкладки.
